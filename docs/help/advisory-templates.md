## What this page is for

Templates control the wording and structure of an advisory's body and subject. The branded header (logo),
the severity banner and the footer (*Generated by ExposureCatalyst* + advisory ID + timestamp) are fixed, so
every advisory stays on-brand.

## How to use it

<!-- requires: template:manage -->
1. Click **New version** on a template. It opens pre-filled with the latest version.
2. Edit the **subject** and **body** and add a change note, then **Save draft version**. The template is
   checked immediately, and errors are shown.
3. Click **Submit**. Another person with `advisory:approve` must **Approve** it. The previous approved version
   is retired, but advisories already created with it keep using it.
<!-- /requires -->
4. New advisories use the latest **approved** version. In the editor you can switch a draft to another
   template.

## Fields and columns

Template bodies use Jinja syntax in a **sandbox**: no access to code, files or the network. Available values:
`advisory.*` (advisory_id, cve_id, severity, title, summary, business_impact, remediation, workaround,
owner_contact, sla_due_date), `cve.*` (cvss, epss, kev, exploit, kev_listed), `exposure.total_unique`,
`product`. Available blocks: `components.summary_table`, `components.validation_matrix` and
`components.section("Title", advisory.remediation)`. Use **inline styles**, because email clients ignore
stylesheets.

## Required permissions

`template:manage` to create and submit versions. `advisory:approve` to approve them, and not for versions you
authored.

## Common errors

- **"template error: …"**: a Jinja syntax error, or a blocked attempt to access internals.
